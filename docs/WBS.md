# 늘봄 — WBS (Work Breakdown Structure)

작업은 저장소 커밋과 현재 코드 기준으로 나눈다.
FitLog AI의 7주 발표 일정표와는 별개이며, 늘봄에 실제로 있는 작업만 적는다.

## 전체 작업

| ID | 작업 | 상태 |
|----|------|------|
| W1 | 백엔드·Flutter 초기 스냅샷 | 완료 |
| W2 | 어르신/보호자 흐름 분리, 건강 화면 정리 | 완료 |
| W3 | 앱 비주얼 정리 | 완료 |
| W4 | 6자리 연결코드, 계정 메뉴 | 완료 |
| W5 | 보호자 어르신 관리 UI | 완료 |
| W6 | README·기술명세서 세트 | 완료 |
| W7 | 서버 인증과 연결코드 동기화 | 남음 |
| W8 | 통화 요약·감정 점수의 서버 연동 | 남음 |
| W9 | FCM 토큰 저장과 조건 푸시 | 남음 |
| W10 | TTS API, 자동화 테스트 | 남음 |

## 세부 작업

### W1 — 초기 스냅샷
- Spring Boot API: 어르신, 통화 기록, Gemini 대화, WebSocket, FCM 테스트
- Flutter 앱 골격과 Firebase 초기화
- PostgreSQL, `DB_PASSWORD`, `GEMINI_API_KEY` 설정

### W2 — 역할 분리
- 역할 선택, 어르신/보호자 가입·로그인 화면
- 어르신 홈 탭(홈, 통화기록, 비상연락)
- 보호자 건강 알림·계정 화면

### W3 — 비주얼
- 어르신 화면 색, Noto Sans KR, 큰 버튼·글자

### W4 — 연결
- 가입 시 6자리 코드 생성
- 어르신 메뉴에서 코드 다시 보기
- 보호자가 코드를 입력해 연결

### W5 — 보호자 관리
- 연결 어르신 선택
- 주간 통화 횟수, 평균 감정, 감정 추이, 최근 알림

### W6 — 문서
- 루트 `README.md`, `AGENTS.md`
- `docs/PLANNING.md`, `ARCHITECTURE.md`, `ADR.md`, `WBS.md`, `SETUP.md`
- 문서 형식은 week3 FitLog AI의 기술명세서 세트를 따른다

### W7 이후 — 남은 서버 연동
- 회원·연결코드를 DB로 이동
- `aiSummary`와 감정 점수를 보호자 차트에 연결
- `/api/fcm/register` 영속화
- `/api/tts` 추가
- 컨트롤러 테스트 작성

## 추적

완료된 W1~W5는 `main`의 커밋 메시지(초기 스냅샷, 흐름 분리, 스타일,
연결코드, 보호자 관리)와 대응한다. W6은 이 문서 커밋이다.
