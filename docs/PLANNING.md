# 늘봄 — 기획서 및 요구사항 정의서

## 1. 프로젝트 비전

혼자 있는 어르신이 매일 AI 친구와 짧게 대화하고, 멀리 있는 보호자가
통화와 건강 신호를 놓치지 않게 하는 돌봄 앱을 만든다.

앱 이름은 늘봄이다. 어르신용과 보호자용 흐름을 나누고, 6자리
연결코드로 둘을 잇는다.

## 2. 문제 정의

- 독거 어르신은 하루 동안 말을 나눌 상대가 적다.
- 보호자는 통화가 없었는지, 컨디션이 나빠졌는지 바로 알기 어렵다.
- 어르신 화면은 글자와 버튼이 커야 하고, 보호자 화면은 여러 어르신을
  한곳에서 봐야 한다.
- 두 사용자를 한 계정 화면에 섞으면 조작이 어려워진다.

## 3. 핵심 요구사항 (기능 요구사항)

| ID | 요구사항 | 설명 | 현재 |
|----|----------|------|------|
| FR-1 | 역할 선택 | 시작 시 어르신 또는 보호자를 고른다 | 구현 |
| FR-2 | 어르신 가입 | 이름, 전화번호로 가입하고 6자리 연결코드를 발급한다 | 로컬 저장 |
| FR-3 | 어르신 로그인 | 전화번호로 로그인한다 | 로컬 저장 |
| FR-4 | 보호자 가입/로그인 | 이메일, 비밀번호(6자 이상) | 로컬 저장 |
| FR-5 | 연결코드 공유 | 어르신이 코드를 다시 볼 수 있다 | 구현 |
| FR-6 | 어르신 연결 | 보호자가 6자리 코드로 어르신을 연결한다 | 로컬 대조 |
| FR-7 | AI 대화 | 짧은 공감 답변을 Gemini로 생성한다 | `POST /api/conversation` |
| FR-8 | AI 친구 이름 | 첫 실행 시 5자 이내 이름을 정한다 | 로컬 저장 |
| FR-9 | 통화 기록 | 최근·오늘·전체 통화 조회와 저장 | API 구현 |
| FR-10 | 비상연락 | 어르신 홈에서 비상연락 탭을 제공한다 | 화면 구현 |
| FR-11 | 보호자 요약 | 주간 통화 횟수, 평균 감정, 감정 추이 | 화면 데이터 |
| FR-12 | 건강 알림 | 경고·확인 목록을 보호자에게 보여 준다 | 화면 데이터 |
| FR-13 | 어르신 관리 API | 등록, 조회, 수정, 삭제, 이름·건강상태 검색 | API 구현 |
| FR-14 | 푸시 | FCM 토큰 등록과 테스트 알림 | 토큰 DB 저장은 미구현 |
| FR-15 | 실시간 메시지 | STOMP로 채팅 메시지를 중계한다 | API 구현 |

건강 상태 값은 `GOOD`(양호), `FAIR`(보통), `POOR`(주의),
`CRITICAL`(위험)이다. 통화 상대 유형은 `AI`, `FAMILY`, `EMERGENCY`이고,
통화 상태는 `COMPLETED`, `MISSED`, `REJECTED`이다.

## 4. 비기능 요구사항

- 어르신 UI는 큰 글씨와 높은 대비를 유지한다. 기본 글꼴은 Noto Sans KR.
- DB 비밀번호와 Gemini 키는 환경변수로만 받는다.
- 앱 기본 API 주소는 Android 에뮬레이터 기준 `http://10.0.2.2:8080`.
- 한국어 UI를 기본으로 한다.

## 5. 향후 확장 계획

- 회원과 연결코드를 PostgreSQL 계정으로 옮긴다.
- 통화 내용 요약(`aiSummary`)과 감정 점수를 저장해 보호자 차트에 연결한다.
- FCM 토큰을 사용자별로 저장하고, 미응답·주의 상태에 푸시를 보낸다.
- `POST /api/tts`를 추가한다.
- 컨트롤러 단위 자동화 테스트를 둔다.
